Queue notifications — design spec

The live ticket follows the customer out of the app: a Live Activity pinned to the lock screen (styled after the in-app join hero), the Dynamic Island while they're elsewhere on the phone, and drop-down banners that mirror the in-app cyan pill. Copy, colors, and hierarchy below are the source of truth for the EAS build.

Behavior
  • Starts when a ticket is created; updates via ActivityKit push tokens as position changes (no polling needed on the lock screen).
  • The progress bar is position-based (people served ÷ people at join), not time-based — it only ever moves forward.
  • “Leave by” uses the GPS travel-time estimate already computed for the departure reminder.
  • Card mirrors the in-app join hero: forest surface, white type, cyan accents, green live dot.

The called state flips the whole card to cyan — the same inversion the in-app pill uses, so the moment reads instantly even at a glance.
  • Time-sensitive interruption level: breaks through Focus modes.
  • Shows the verification code so the customer can walk straight up without unlocking.
  • Auto-dismisses (activity ends) when served, no-show, or left.

Banner rules — banners are the in-app cyan pill, verbatim:
  • Called → cyan banner (the only cyan one; reserved for “your turn”).
  • Progress, departure, and requeue updates → forest banner, green dot.
  • No-show → forest banner, red dot, rejoin deep-link.
  • Every banner deep-links to the Ticket screen.
  • Android equivalent ships today: sticky “live ticket” notification on the live-ticket channel + heads-up alerts on queue-alerts (implemented in lib/notifications.ts).

5 · Build requirement

iOS Live Activities and the Dynamic Island require an ActivityKit widget extension — a native target that Expo Go cannot run. Ship path: EAS dev build with a config plugin (e.g. expo-live-activity) + APNs push-to-update tokens so the backend drives position changes. The Android side (persistent live-ticket notification + max-importance call alerts) requires no extra build steps and is already implemented.
