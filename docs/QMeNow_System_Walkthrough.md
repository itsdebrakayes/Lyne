# Q ME NOW — System Walkthrough & Test Report

This document outlines the final state of the Q ME NOW monorepo after the full architecture split and integration. It serves as a test report, a demo script, and a technical walkthrough of how the 5 components interact in a production-like environment.

## 1. System Architecture

The monolithic React/Supabase application has been successfully split into a 5-component enterprise architecture, all orchestrated via Docker Compose.

| Component | Stack | Role | Status |
|---|---|---|---|
| **Backend API** | Node.js, Express, MySQL | Central source of truth. Handles queues, RBAC, and data persistence. | ✅ Passing |
| **User Website** | React, Vite, Tailwind | Public discovery, branch search, and web-based queue joining. | ✅ Passing |
| **Mobile App** | React Native, Expo | Persistent user sessions, saved businesses, and live queue tracking. | ✅ Passing |
| **Admin Desktop** | Electron, React, Vite | Secure, role-based dashboards (Staff, Manager, Executive) packaged as `.exe`. | ✅ Passing |
| **Predictive Model** | Python, Jupyter, scikit-learn | Offline batch pipeline for best-time predictions and peak hour heatmaps. | ✅ Passing |

*Note: Supabase is now used exclusively for Authentication (JWT generation). All application data, including user profiles, is stored in MySQL.*

## 2. End-to-End Demo Script

Follow this script to demonstrate the full capabilities of the Q ME NOW platform.

### Setup (1 minute)
1. Ensure Docker is running.
2. In the root directory, run: `docker compose up -d`
3. Wait 30 seconds for MySQL to initialize and run the seed scripts.
4. Verify the API is healthy: `curl http://localhost:4000/api/queues` (should return a JSON array of queues).

### Scenario A: The New Customer (Mobile App)
1. Open the mobile app (or run `npm run web` in `apps/mobile`).
2. Click **Create Account**. Enter a name, email, and password.
   *Behind the scenes: Supabase creates the user, and the app calls `POST /api/auth/sync-user` to mirror the profile into MySQL.*
3. Complete the **Onboarding Screen** by selecting "TAJ" and "NHT" as favourite businesses.
4. On the **Home Screen**, observe the saved businesses at the top.
5. Tap **TAJ** → **Kingston Branch** → **Driver's License Renewal**.
6. Note the "Best time to visit" prediction at the top of the screen (generated by the Jupyter model).
7. Tap **Join Queue**, fill out the intake form, and observe the live ticket screen pulsing "Waiting".

### Scenario B: The Line Staff (Admin Desktop)
1. Open the Admin Desktop App (run `npm run dev` in `apps/admin-desktop`).
2. Log in with the staff demo account (`staff@qmenow.com` / `password`).
3. The app routes you to the **Staff Dashboard**.
4. The dashboard automatically fetches the staff member's counter assignment for the day (e.g., "Counter 3 - Driver's License").
5. The queue list shows the customer from Scenario A.
6. Click **Call Next**. 
   *Behind the scenes: `PUT /api/tickets/:id/status` updates the ticket to 'serving'.*
7. Observe the Mobile App instantly update to a yellow "You're up!" state.
8. Click **Complete**. The ticket disappears from the queue, and a wait-time analytics record is silently written to MySQL.

### Scenario C: The Executive (Admin Desktop)
1. Log out of the Staff account and log in with the executive demo account (`exec@qmenow.com` / `password`).
2. The app routes you to the **Executive Dashboard**.
3. View the cross-branch analytics:
   - Average wait times across Kingston vs. Montego Bay.
   - The 7-day rolling performance trend chart.
   - The heatmap showing peak hours (Mondays at 9 AM).
4. Click **Export Report** to download the raw CSV data.

## 3. Integration Fixes & Technical Notes

During the final integration phase, several critical bugs were identified and fixed to ensure the system works end-to-end:

1. **Route Ordering Conflict (`tickets.js`)**
   - *Issue:* The backend route `GET /api/tickets/queue/:queue_id` was declared after `GET /api/tickets/:id`. Express matched the word "queue" as a ticket ID, causing 404 errors on the Staff Dashboard.
   - *Fix:* Reordered the routes so the specific `/queue/` path is evaluated before the generic `/:id` parameter.

2. **Missing Staff API Functions (`staff.ts`, `queue.ts`)**
   - *Issue:* The Admin Desktop app relied on helper functions (`fetchMyQueue`, `fetchMyCounterAssignment`) that were removed during the MySQL migration.
   - *Fix:* Rewrote these functions to query the new MySQL backend endpoints (`/api/assignments` and `/api/queues`).

3. **Type Definition Mismatches (`types/queue.ts`)**
   - *Issue:* The frontend TypeScript interfaces expected Supabase column names (`client_id`, `organization_id`), but the MySQL API returned standard relational names (`user_id`, `business_id`).
   - *Fix:* Updated the interfaces to accept both sets of keys, ensuring backward compatibility with older React components while supporting the new backend.

4. **Mobile App Completeness**
   - *Issue:* The mobile app was missing the `SignupScreen` and the `OnboardingScreen` (for selecting favourite businesses).
   - *Fix:* Built both screens. The Onboarding screen uses a `Set` to track selections and bulk-POSTs them to the `/api/saved` endpoint before navigating to the main tab flow.

5. **Auth Sync Middleware (`useAuth.ts`)**
   - *Issue:* When a user signed up on mobile, their profile wasn't appearing in MySQL, causing foreign key errors when they tried to join a queue.
   - *Fix:* Updated the `signUp` method to catch the user metadata and immediately POST it to `/api/auth/sync-user` before resolving the signup promise.

## 4. Build Instructions

### Local Development
```bash
# 1. Start the database and API
docker compose up -d

# 2. Start the User Website (Port 5173)
cd apps/website && npm run dev

# 3. Start the Admin Desktop App (Port 5174)
cd apps/admin-desktop && npm run dev

# 4. Start the Mobile App (Expo Go)
cd apps/mobile && npm start
```

### Packaging the Admin Desktop App (.exe)
To build the Windows installer for the administrative staff:
```bash
cd apps/admin-desktop
npm install
npm run build:win
```
The installer will be generated in `apps/admin-desktop/release/Q ME NOW Admin Setup 1.0.0.exe`.

### Running the Predictive Model
To update the "Best time to visit" predictions with the latest data:
```bash
cd apps/model
python3 scripts/export_csv.py          # Pulls the last 90 days from MySQL
jupyter nbconvert --to notebook --execute notebooks/05_predictive_model.ipynb
python3 scripts/import_predictions.py  # Pushes new insights back to MySQL
```
